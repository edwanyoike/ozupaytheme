1. Prerequisites

WordPress and WooCommerce

  • WordPress 6.0 or later
  • WooCommerce 7.0 or later installed and activated
  • PHP 8.0 or later
  • An SSL certificate on your domain (HTTPS). Daraja will not deliver callbacks to HTTP-only sites

Safaricom Daraja account

Register at developer.safaricom.co.ke and create an application with these APIs enabled:

APIRequired for
M-Pesa Express (STK Push)All payment flows
C2BC2B Buy Goods Fallback + C2B URL registration
B2CB2C Auto-Refunds feature only

What you need from the Daraja portal

These four values come from Safaricom's Daraja portal, not from OzuPay — where exactly they live inside that portal is Safaricom's to change, so check the Daraja portal itself (or your app's documentation there) rather than relying on a fixed menu path here.

  • Consumer Key: found in the Daraja portal, under your app
  • Consumer Secret: found in the Daraja portal, under your app
  • Business Shortcode: your Paybill or Till/Buy Goods number
  • Passkey: found in the Daraja portal, under your app

OzuPay license key

Purchase at ozupay.com. Your license key is at My Account → Licenses after purchase.

2. Installation

Free Edition

Step 1: Install from WordPress.org

  1. Go to Plugins → Add New in WordPress admin.
  2. Search for OzuPay Payment Gateway for M-Pesa (the plugin's listing title on WordPress.org — you'll see it referred to as "OzuPay M-Pesa" or "OzuPay M-Pesa Payments" once installed, in the admin menu and elsewhere).
  3. Click Install Now on the OzuPay result, then Activate Plugin.

Step 2: Verify

After activation you will see an OzuPay M-Pesa menu in the WordPress sidebar. No license key is required for the Free edition.

OzuPay automatically creates its database tables and schedules background jobs on first activation. No manual database steps are required.

Updating the Free edition

Updates appear in Dashboard → Updates like any WordPress.org plugin. Click Update Now. Your settings and transaction log are preserved.

Pro Edition

Step 1: Download

  1. Log in at ozupay.com → My Account → Licenses.
  2. Click Download Plugin next to your license.
  3. Save ozupay.zip to your computer.

Step 2: Upload to WordPress

  1. If the Free edition is active, deactivate and delete it first. Pro includes all Free features.
  2. Go to Plugins → Add New in WordPress admin.
  3. Click Upload Plugin.
  4. Choose ozupay.zip and click Install Now.
  5. Click Activate Plugin.

Step 3: Activate your license

Go to OzuPay → License, paste your license key, and click Activate License. See Section 3 for details.

Step 4: Verify

After activation and license entry you will see the full OzuPay M-Pesa menu including Dashboard, Analytics, and all Pro feature settings.

OzuPay automatically creates its database tables and schedules background jobs on first activation. No manual database steps are required.

Updating the Pro edition

Pro does not auto-update through WordPress's Dashboard → Updates screen. Every update is a manual download-and-upload. When a new version is available, a dashboard widget shows a Download button, and an admin notice appears on the Plugins list. Download the ZIP (from the widget or from ozupay.com → My Account → Licenses) and install it via Plugins → Add New → Upload Plugin. If no update notice appears, go to OzuPay → About → Check for Updates to force a fresh check.

3. License Activation Pro

  1. Go to OzuPay → License.
  2. First, click Connect to ozupay.com and complete the popup authorization. Activation is blocked until your site is connected to your ozupay.com account.
  3. Paste your license key and click Activate License.
  4. OzuPay contacts the license server and shows a green "Active" status.

The license is cached: OzuPay doesn't call the license server on every page load. Without an active license, the core STK Push gateway still works; only premium features are restricted.

Transferring a license

  1. On the old site: OzuPay → License → Deactivate License.
  2. On the new site: enter the key and click Activate.

Activating without deactivating first shows: "All activation seats for this license are in use. Deactivate another domain first, then try again." If you cannot access the old site, contact support to force-deactivate.

4. Daraja Credentials Setup

Go to OzuPay → Settings → Credentials. OzuPay → Settings is organized into tabs: Checkout Settings (Section 5), Credentials (Daraja Credentials below, plus Verify Callback IP and Log Retention), Premium Features (Section 7), Testing & C2B Pro (C2B URL Registration — Section 6 — plus sandbox testing tools and a health check), Plugin Data (Usage Data and Danger Zone), and Export / Import Pro (Section 7). The Free edition shows four tabs — Checkout Settings, Credentials, Features, Plugin Data — since Testing & C2B and Export / Import both depend on Pro-only features.

Consumer Key, Consumer Secret, and STK Passkey come from Safaricom's Daraja portal, not from OzuPay — exactly where they sit inside that portal is Safaricom's to change without notice, so treat "found in the Daraja portal" as the reliable answer rather than a specific tab name.
OzuPay encrypts five sensitive fields (Consumer Key, Consumer Secret, STK Passkey, and the B2C Initiator Name / Security Credential) and masks them once saved; leaving one of those blank on save keeps its existing value. Business Shortcode and Customer-Facing Number are stored as plain text and are not covered by that "leave blank to keep" behavior. Always re-enter them when saving other settings.

5. Gateway Configuration

Go to WooCommerce → Settings → Payments. In the Payment providers list you'll see M-Pesa and, if enabled, M-Pesa on Delivery. Click Manage next to the one you want to configure. There is no listing literally called "OzuPay M-Pesa"; that's just the plugin's internal name for the gateway.

The same Title/Description/Phone field label/Manual Instructions/STK Push Retries fields are also editable from OzuPay → Settings → Checkout Settings. Both screens read and write the same settings, so editing either one keeps them identical — use whichever you already have open.

SettingDescription
Enable / DisableToggles M-Pesa on the checkout page
TitlePayment method name customers see
DescriptionText shown under the payment method
Phone field labelLabel for the M-Pesa number input
Manual Payment InstructionsText shown when STK Push fails, explaining how to pay directly as a fallback
STK Push Retry AttemptsHow many times OzuPay automatically retries the STK Push before falling back to manual payment options
Transaction Logging and Verify Callback IP are not on this gateway screen. They are global toggles on the Credentials tab of OzuPay → Settings (Section 4).

6. Registering C2B Callback URLs Pro

Required for C2B Buy Goods Fallback and M-Pesa on Delivery. OzuPay registers two URLs with Safaricom:

  • Validation URL: Safaricom asks OzuPay before accepting a payment
  • Confirmation URL: Safaricom notifies OzuPay after payment is processed

Go to OzuPay → Settings → Testing & C2B and scroll to the C2B URL Registration section, then click Register C2B URLs. Re-register whenever you switch environments or change your domain. There is no "Regenerate Callback Token" feature. The token generated on activation is permanent.

Sandbox accepts registration but may not deliver callbacks actively. Use the Daraja portal's Simulate C2B tool for sandbox testing.
If your site's URL changes (e.g. a domain migration), OzuPay shows a "C2B callback URL prefix changed" admin notice on every admin screen until it's resolved. If you already re-registered from this tab, the notice clears on its own. If you separately confirmed with Safaricom that they have the current URL, click "Already registered — dismiss this notice" directly on the notice instead of returning to this tab.

7. Feature Configuration Pro

All features below are available in the Pro edition. Enable each from OzuPay → Settings → Premium Features. Disabling a feature never deletes its settings. Re-enabling restores them.

M-Pesa on Delivery (COD Deposit) Pro

Customers pay a configurable deposit at checkout; the balance is collected on delivery.

Configure at WooCommerce → Settings → Payments → M-Pesa on Delivery (this gateway has its own settings screen, like the main M-Pesa gateway), or OzuPay → Settings → Checkout Settings → M-Pesa on Delivery sub-tab — Checkout Settings splits M-Pesa and M-Pesa on Delivery into separate sub-tabs so you don't scroll past one gateway's fields to reach the other's, and both screens stay in sync.

SettingDescription
Deposit modelShipping Fee (default), Fixed Fee, or Percentage of Cart
Deposit amountThe fixed amount or percentage (1–100), depending on the model
Auto-Cancel Timeout (hours)Hours to pay before the order is auto-cancelled. Default: 2, range 1–72

There is no separate "Delivery phone" field. Delivery agents collect the balance from the delivery portal or collection link, which sends the STK Push to the customer's own phone.

Customer checkout flow

  1. Customer selects M-Pesa on Delivery, enters phone, places order.
  2. STK Push sent for the deposit amount only.
  3. Customer enters PIN. Order moves to Awaiting COD Collection.
  4. Deposit confirmation email sent with receipt and balance due.

Delivery flow

  1. Agent opens the delivery portal or collection link.
  2. Clicks Send Payment Prompt: STK Push sent to customer for the balance.
  3. Customer pays. Order moves to Processing/Completed.
  4. If customer refuses: agent clicks Reject. Order reverts.

Auto-cancel: If the deposit is not paid within the expiry window, OzuPay's cron job (runs every 30 minutes) cancels the order and emails the customer. The deposit is not automatically refunded.

C2B Buy Goods Fallback Pro

When STK Push fails, customers can pay directly to your Paybill/Till. OzuPay matches the incoming C2B payment to the order automatically.

To enable: toggle on + register C2B URLs (Section 6).

  1. STK Push fails or times out.
  2. Customer is shown the Payment Issue page with your number, amount, and account number.
  3. Customer pays via Safaricom My One App or USSD.
  4. Safaricom delivers C2B confirmation to OzuPay.
  5. OzuPay matches the payment to the order. Waiting page redirects to thank-you page.

Underpayments are detected and the order placed on hold. There is no separate admin-alert email for this specific case. Check OzuPay → Transaction Log or the Unmatched C2B screen.

Manual Verification Fallback Pro

Customers submit their M-Pesa transaction code. Verification is fully automated: OzuPay queries Daraja's Transaction Status API and confirms or rejects the order itself. There is no admin approve/reject step in the checkout flow.

Customer flow

  1. The fallback page shows an "I already paid" section.
  2. Customer enters their code (exactly 10 uppercase alphanumeric characters, e.g. SGR7H2K9X1) and submits.
  3. Rate-limited to 5 attempts per order, plus 10 attempts per IP per 15 minutes.
  4. OzuPay automatically verifies the code against Daraja and confirms or rejects the order within seconds. No admin review step.

The POS REST API exposes separate confirm-code/reject-code endpoints for cashier-driven review of POS orders specifically; that manual workflow applies only to the POS integration, not to regular checkout.

B2C Auto-Refunds Pro

WooCommerce refunds trigger automatic M-Pesa payments to the customer's phone via Daraja B2C.

Enable B2C Automatic Refunds in Premium Features. The credential fields then appear inline under that feature card (there is no separate "B2C" tab).

SettingWhere to find it
B2C Initiator NameFound in the Daraja portal, under your app's B2C setup
B2C Security CredentialFound in the Daraja portal, under your app's B2C setup
B2C ShortcodeYour B2C shortcode (may differ from the STK Push shortcode)

To refund: open the order → in the OzuPay M-Pesa panel click Refund via M-Pesa → adjust the amount if partial → confirm. The WooCommerce refund record is created only after Safaricom confirms the transfer, not at initiation. The result appears as an order note within seconds. If a refund fails, there is currently no separate alert email. Check the Transaction Log or order notes.

Analytics Dashboard Pro

Payment metrics at OzuPay → Dashboard, reorganized around net collections and anything needing action. Daily figures are also rolled up nightly at 00:05 server time. Exportable as CSV.

KPI cards: Net Collected, STK Success Rate, Avg Collected Payment, Avg Time to Pay, Refunds Issued, and (for M-Pesa on Delivery) Deposits Collected / COD Balance Collected as raw KES totals. A separate STK summary widget shows counts (not percentages) for Initiated, Confirmed, Failed, Success Rate, C2B Fallbacks, Manual Verified, and Auto-Cancelled. A Work Requiring Attention panel lists anything that needs a look — failed or timed-out STK attempts, unmatched C2B payments, COD balances awaiting collection — each linking straight to the screen to resolve it.

Advanced Admin Tools Pro

  • OzuPay → Unmatched C2B: list C2B payments that couldn't be auto-matched. Click a row to open a Match-to-Order modal (there is no separate "Dismiss" action).
  • OzuPay M-Pesa meta box: context-dependent buttons such as Send M-Pesa Prompt / Send Deposit Request, Query STK Status, and (for M-Pesa on Delivery orders only) Mark Deposit Paid / Mark Balance Collected. There is no generic "Mark as Paid" button for regular STK orders.
  • OzuPay → System Info: full environment report. Click Copy to Clipboard and send to support when reporting issues.

Admin Failure Alerts Pro

Sends an email when: an STK Push initiation fails, an order was cancelled but later paid anyway, or STK Push succeeded but the confirmation callback never arrived. There is currently no alert for a failed B2C refund or a callback rejected by IP filtering. No configuration needed beyond enabling the feature. Alerts go to OzuPay's Notification Email if set, otherwise your site's admin email, not specifically WooCommerce's Store email field.

Scheduled Email Reports Pro

Enable in Premium Features. The sub-settings expand inline below the toggle (there is no separate "Reports" page).

SettingOptions
FrequencyDaily, Weekly, or Monthly
RecipientsComma-separated email addresses

Reports include: Gross Payment Volume, Net Revenue, Deposits/Balances Collected, STK Initiated/Confirmed/Failed counts and Success Rate, Refunds Issued, and Auto-Cancellations. There is no payment-path breakdown or "top failure reasons" list.

POS REST API Pro

A REST API for building POS applications (tablet apps, back-office tools) that create orders and handle M-Pesa payments without a WooCommerce cart session.

Setup: Enable the feature, then generate WooCommerce API keys at WooCommerce → Settings → Advanced → REST API. Set Permissions to Read/Write. Use the Consumer Key and Consumer Secret for HTTP Basic Auth on all API calls.

See Section 13: POS API Reference for the full endpoint list with request and response examples.

Export / Import Settings Pro

Available at OzuPay → Settings → Export / Import, gated behind the Advanced Admin Tools premium feature — enable that under Premium Features first, or the tab shows a message pointing you there instead of the export/import tools.

Export downloads a JSON file covering your OzuPay settings and both gateways' settings (M-Pesa and M-Pesa on Delivery). Daraja credentials (Consumer Key/Secret, STK Passkey, B2C Initiator Name/Security Credential) are always stripped — re-enter them manually on the destination site. The Callback Token is excluded by default too; including it is an explicit opt-in at export time, and importing a file that contains one requires a second explicit confirmation before OzuPay applies it.

Import reads back a previously exported file and shows a preview of what it found — which settings, whether credentials or a token are present — before you confirm applying it.

8. Going Live

Use OzuPay → Go-Live Checklist to track progress. Steps in detail:

  1. In OzuPay → Settings → Credentials, under Daraja Credentials → Environment, switch to Production.
  2. Enter your production credentials (Consumer Key, Consumer Secret, STK Passkey) from your live Daraja app. Leave fields blank to keep existing values.
  3. In OzuPay → Settings → Testing & C2B, C2B URL Registration section, click Register C2B URLs for production (required even if registered in sandbox).
  4. In OzuPay → Settings → Credentials, set Verify Callback IP to Yes (this is a global OzuPay setting, not a per-gateway one).
  5. Test with a real transaction: place an order, enter a real Safaricom number, approve the STK Push.
  6. In OzuPay → Transaction Log, confirm it shows stk_initiated (Result: 0) and stk_confirmed (Result: 0).
  7. Confirm order status: the test order should be Processing or Completed.

9. Customer-Facing Payment Flow

Standard STK Push

  1. Customer selects M-Pesa, enters phone (07XXXXXXXX or 254XXXXXXXXX; OzuPay normalises all formats).
  2. Clicks Place Order.
  3. OzuPay sends an STK Push. Customer's browser goes to the Payment Waiting screen showing the order amount and a 90-second polling window.
  4. Customer's phone receives the M-Pesa PIN prompt.
  5. Customer enters PIN and approves.
  6. Success: waiting screen detects the callback and redirects to the thank-you page with the M-Pesa receipt.
  7. Failure/timeout: payment issue page is shown with options to pay directly or submit a code manually (depending on enabled features).

M-Pesa on Delivery

  1. Customer selects M-Pesa on Delivery. Checkout shows the deposit amount and balance due on delivery.
  2. STK Push sent for deposit only.
  3. Order moves to Awaiting COD Collection. Customer receives deposit confirmation email.
  4. Balance collected on delivery by the delivery agent (see Section 10).

10. Delivery Portal Pro

URL: https://yourstore.co.ke/ozupay/delivery/

Requires WordPress login with the ozupay_delivery_agent role or manage_woocommerce capability.

Creating a delivery agent account

  1. WordPress admin → Users → Add New.
  2. Enter username, email, password.
  3. Set Role to OzuPay Delivery Agent.
  4. Click Add New User and send credentials to the agent.

Collecting a balance

  1. Agent opens the portal: see all orders in Awaiting COD Collection status.
  2. Taps the order, then Send Payment Prompt: STK Push sent to customer.
  3. Portal updates to Collected when Daraja confirms.

Cash collection: tap Collect Cash to record a cash payment without STK Push.

Rejection: tap Mark as Rejected if the customer refuses delivery.

Per-order collection link

A secure, login-free link valid for 48 hours. Find it in the OzuPay meta box on the order edit screen. Send to agents via WhatsApp or SMS. The link can't be guessed: it's an HMAC-SHA256 token derived from the order ID and phone number.

14. Webhook Reference Pro

Setup

Webhooks are a premium feature built on WooCommerce's native webhook system (extra topics/resources, not a separate delivery mechanism).

  1. Enable Webhook Enrichment in Premium Features (OzuPay's topics appear in the dropdown regardless; this toggle only controls whether the ozupay payload data is attached).
  2. Go to OzuPay → Webhooks → Add Webhook.
  3. Enter: Name, Delivery URL (HTTPS, publicly reachable), Secret (your chosen signing key), Topic.
  4. Click Save. There is no test-ping-on-save: trigger a real event to confirm delivery.

Signature verification

Every delivery includes an X-WC-Webhook-Signature header. Verify it to confirm the request is from OzuPay.

PHP

$body      = file_get_contents('php://input');
$signature = base64_encode(hash_hmac('sha256', $body, 'your_secret', true));
if (!hash_equals($signature, $_SERVER['HTTP_X_WC_WEBHOOK_SIGNATURE'])) {
    http_response_code(401);
    exit('Invalid signature');
}

Node.js

const crypto = require('crypto');
const sig = crypto.createHmac('sha256', 'your_secret')
  .update(rawBody).digest('base64');
if (sig !== req.headers['x-wc-webhook-signature']) {
  return res.status(401).send('Invalid signature');
}

Delivery headers

Content-Type: application/json
X-WC-Webhook-Topic: ozupay.payment.confirmed
X-WC-Webhook-Signature: <base64-hmac-sha256>
X-WC-Webhook-Source: https://yourstore.co.ke

Retries

If your endpoint returns non-2xx or does not respond within 5 seconds, WooCommerce retries: 1 min, 2 min, 4 min, 8 min, 16 min, 32 min (6 total). After 6 failures the webhook is disabled. Re-enable at WooCommerce → Settings → Advanced → Webhooks.

  4. Click Run Once in Make and trigger a test event.
  5. Make captures the payload structure: use the visual mapper to route fields to subsequent modules.

15. Updates Pro

Pro does not auto-update through WordPress's Dashboard → Updates screen. Every update is manual. A dashboard widget shows a Download button when a new version is available, and an admin notice appears on the Plugins list. Download the ZIP and install it via Plugins → Add New → Upload Plugin. Settings and data are preserved.

If no update notice appears: go to OzuPay → About → Check for Updates (this button is on the About page, not the License page). If still missing, download the ZIP manually from ozupay.com and re-upload the same way.

16. Troubleshooting

STK Push not reaching the customer's phone

Step 1: Check OzuPay → Transaction Log for stk_initiated. If missing, OzuPay never called Daraja. Check PHP error logs.

Step 2: Open the row and check the response field. A successful initiation shows "ResponseCode": "0".

Step 3: Check Daraja result codes on the stk_confirmed/stk_failed row:

CodeMeaningFix
0SuccessNone needed
1Insufficient M-Pesa balanceCustomer tops up
1032Cancelled by userCustomer dismissed the prompt
1037Timeout: customer unreachableCustomer's phone was off or out of signal
2001Wrong PINCustomer retries
9999Daraja internal errorRetry; report to Safaricom if persistent

Safaricom's full Daraja ResultCode reference sits behind a developer-account login rather than a public page, so the table above reflects commonly observed and reported values, not a screenshot of an official public document.

An "Invalid TransactionType" error at initiation (not a Daraja result code) usually means the Shortcode Type setting (Paybill vs Till) is wrong, because that setting controls the TransactionType value OzuPay sends to Daraja, and a value that doesn't match your actual Shortcode is rejected before a payment is even attempted. See Section 4.

Callbacks not being received

Step 1: Your callback URL (shown at OzuPay → System Info) includes a required ?token= query argument and only accepts POST. A bare curl -I (HEAD, no token) will be rejected before OzuPay even checks the IP, so it isn't a reliable connectivity test on its own.

Step 2: Check whether the callback URL in your Daraja app configuration matches exactly what OzuPay uses, including the token (shown in OzuPay → System Info). This is the most common cause and needs no changes to your site to check.

Step 3: If the URLs match and you have Verify Callback IP enabled, temporarily disable it and test. Safaricom IP ranges OzuPay allowlists: 196.201.210.0/24, 196.201.212.0/24, 196.201.213.0/24, 196.201.214.0/24, 196.201.218.0/24, 196.201.219.0/24, 196.201.220.0/24, 196.201.221.0/24. Confirm these aren't blocked by your firewall. (Safaricom doesn't publish this range on a stable public page, so treat it as commonly reported rather than a linked official source, and re-verify if callbacks still don't arrive.)

Order status not updating after payment

If an stk_confirmed event with result 0 appears in the log but the order is still Pending:

  • Open the log row and confirm CallbackMetadata contains Amount and MpesaReceiptNumber.
  • Check PHP error logs (wp-content/debug.log) for exceptions.
  • Test with other payment gateway plugins deactivated.

C2B payments not received

  • Re-register C2B URLs: OzuPay → Settings → Testing & C2B, C2B URL Registration section → Register C2B URLs. Success message: "C2B URLs registered successfully with Safaricom."
  • Confirm the shortcode matches the Business Shortcode on the Credentials tab of OzuPay → Settings.
  • In sandbox, use Daraja's Simulate C2B tool for controlled testing.

Data export

When a WordPress admin uses Tools → Export Personal Data, OzuPay includes all M-Pesa phone numbers and receipt codes from the customer's orders in the standard WooCommerce export.

Data erasure

When Tools → Erase Personal Data is processed, OzuPay replaces the M-Pesa phone number in order meta with a masked placeholder (e.g. 254XXXXXXXXX): masking, not a cryptographic hash. Receipt codes are retained for financial audit purposes. The raw transaction log payload and response for that order's rows are overwritten with [erased]. The wp_ozupay_customer_risk table is not currently covered by this erasure routine.

Transaction log retention

Configure "Log Retention (days)" on the Credentials tab of OzuPay → Settings, alongside the Daraja Credentials fields. Range: 30–3650 days. Default: 365 days. Security events are always purged after 30 days regardless of this setting.
